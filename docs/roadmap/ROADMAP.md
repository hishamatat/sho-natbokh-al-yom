# شو نطبخ اليوم؟ — Roadmap

Roadmap Version: 1.1  
Status: Accepted Direction — Implementation requires per-batch GO  
Last Updated: 2026-09-29

## استراتيجية الطريق وحدود الإذن

**Decision Engine + Household Memory for Arab families.** مرجع المعمارية الحاكم: [Architecture v1.1](../architecture/ARCHITECTURE.md). الاستراتيجية: Permanent Web/PWA-first مع backend متعدد العملاء. الكويت للتحقق أولًا، والسعودية أول سوق للتوسع بالحجم بعد تحقق سعودي مستقل.

**M00 → V00 → V00 Decision Gate GO/MODIFY/STOP → M01–M31 فقط بعد GO.** كل دفعة لها عقد صغير وموافقة صريحة خاصة بها. اعتمد المالك M00 وأعطى GO لـV00 اليدوية بشرط أن تكون كل العائلات بلا معرفة أو علاقة سابقة به. V00 في مرحلة التجهيز ولم يبدأ التواصل، وM01 وبقية الدفعات غير مبدوءة.

Pantry اختيارية: لا onboarding إجباري للمكونات، وpantry=empty حالة طبيعية. السياق الأساسي: أشخاص ووقت وفئة ميزانية وذوق وما لا نريده اليوم وتاريخ وإعدادات العائلة. M18/M19/M20 لا تعتمد على M14/M15 أو على عناصر مخزون. فرع Pantry يحسن المطابقة عند توفر بيانات فقط.

## سير العمل المشترك لكل Batch

Architecture Review / review of current state → Decisions → Mini-Contract → explicit GO → Implementation → Targeted Tests → Affected Tests → Full Regression → UI Smoke → Final Diff Review → Commit Approval → Commit

لا commit دون موافقة مستقلة بعد Final Diff Review. كل Mini-Contract يحدد الملفات والنطاق والاختبارات والمخاطر والكلفة والقبول والرجوع. اختبارات البطاقات أمثلة مستهدفة؛ تضاف Affected Tests وFull Regression التراكمية وUI Smoke حسب سير العمل. الدفعات الوثائقية/البحثية تستبدل اختبار الكود بمراجعة اتساق الأدلة ولا تنشئ برنامجًا.

Expected files/modules توقعات وليست ملفات مأذونًا بإنشائها الآن؛ DB/API/UI تعني تغييرات مستقبلية عند GO. قبل كل دفعة تراجع الحالة الفعلية بدل افتراض أن سابقتها نفذت. الأرقام ترتيب معرفات وليست وعدًا بزمن أو إذن تنفيذ متسلسل تلقائي.

## M00 وبوابة التحقق قبل البرمجة

### M00 — اعتماد مراجعة PWA-first

- **Goal:** إغلاق التباس النطاق والبوابات قبل أي تجربة أو كود.
- **Scope:** مراجعة Architecture v1.1 والـADRs والسوق الكويتية وV00 وOptional Pantry وحدود الموافقات؛ اعتماد النطاق والقرارات المفتوحة.
- **Out of Scope:** كل تنفيذ وملفات ومشروع وحسابات وشراء.
- **Expected files/modules:** `docs/contracts/M00_REVIEW.md` لسجل المراجعة، و`docs/contracts/V00_MINI_CONTRACT.md` للعقد التالي المقترح؛ لا ملفات برمجية. المسارات البرمجية تقديرية للمستقبل فقط.
- **DB changes:** لا تغييرات.
- **API changes:** لا تغييرات؛ مراجعة تصور العقود.
- **Web/PWA UI changes:** لا تغيير؛ مراجعة رحلات الورق.
- **Tests:** مراجعة رحلة زائر، مستخدم PWA، ومستخدم Native مستقبلي بنفس الحساب.
- **Manual smoke:** مراجعة خمس رحلات: عام، حساب، قرار دون Pantry، قراءة offline، Native مستقبلي بنفس الحساب.
- **Exit criteria:** الاتجاه وحدود V00 معتمدان والقرارات المفتوحة لها مالك وموعد؛ لا إذن كود ضمني.
- **Dependencies:** قراءة الحالة الحالية واعتماد نطاق مراجعة M00 تحديدًا.
- **Cost/account impact:** صفر؛ لا حساب مطلوب.

### V00 — Demand Validation Sprint في الكويت

- **Goal:** اختبار الحاجة والقبول والعودة الطوعية قبل الكود.
- **Scope:** Concierge يدوي مع 15–20 عائلة كويتية بعد اعتماد خطة التجربة؛ سؤال Pantry اختياري، وذاكرة تفضيلات ووجبات بسيطة. هذه البطاقة توثق عملًا مستقبليًا فقط.
- **Out of Scope:** برمجة أو خدمات أو AI أو حسابات منتج أو تعميم سعودي أو افتراض CAC؛ لا تواصل ضمن مهمة إعداد الوثائق.
- **Expected files/modules:** `docs/business/VALIDATION_PLAN.md` مرجع الخطة و`docs/contracts/V00_MINI_CONTRACT.md` عقد التشغيل اليدوي؛ عند GO تحدد أداة خاصة لسجل البحث وتقرير مجهّل. لا تنشأ بيانات مشاركين داخل المشروع أو عقود برمجية.
- **DB changes:** لا قاعدة بيانات؛ سجل يدوي محدود برموز منفصلة عن بيانات الاتصال.
- **API changes:** لا API.
- **Web/PWA UI changes:** لا UI؛ WhatsApp أو نموذج بسيط قناة محتملة بعد الموافقة، وليس خدمة تنشأ الآن.
- **Tests:** مراجعة خطة/موافقة وسلامة محتوى، تعريف المقامات والتمييز بين طلب طوعي وموجّه وعدم الرد.
- **Manual smoke:** محاكاة ورقية بجلسة افتراضية دون Pantry، رفض جميع الخيارات، عودة طوعية وطلب حذف، دون مشارك حقيقي.
- **Exit criteria:** Validation Plan ومعايير المشاركين ورسائل ومخطط بيانات ومقاييس وأسئلة مقابلة وقالب تقرير ومعايير GO/MODIFY/STOP واضحة؛ عند تنفيذ V00 لاحقًا يلزم نتائج حقيقية وتقرير وبوابة موقعة، لا مجرد وجود الخطة.
- **Dependencies:** M00 واعتماد Mini-Contract وGO مستقل لتشغيل V00، ومسؤول/سياسة بيانات ووقت بحث ومحتوى مراجع.
- **Cost/account impact:** لا تكلفة/حساب في إعداد الخطة؛ التجربة الفعلية لها وقت مؤسس ومحتوى ودعم وربما حوافز معتمدة، تسجل منفصلة عن cash software.

### V00 Decision Gate — GO / MODIFY / STOP

هذه بوابة وليست Batch برمجية. تطبق معايير [Validation Plan](../business/VALIDATION_PLAN.md) المحددة قبل التجربة، مع عرض أعداد ومقامات وحدود العينة.

- GO: دليل قبول وعودة طوعية وقيمة دون إلزام Pantry، دون عائق سلامة/خصوصية؛ يسمح بالانتقال لمراجعة M01 فقط.
- MODIFY: فرضية واحدة قابلة للاختبار مع عينة/نافذة أو محتوى أو إدخال يحتاج تصحيحًا؛ إعادة تجربة محدودة قبل الكود.
- STOP: إيقاف البناء الحالي عند غياب قيمة متكررة بعد تحقق كافٍ أو تعذر الخدمة الآمنة؛ لا يحوّل ضعف الدليل إلى إذن تقني.
- التقرير يسجل المالك والتاريخ والدليل والقرار والخطوة التالية. GO العام لا يغني عن Mini-Contract وGO لـM01.

## M01–M31 — بعد بوابة GO وموافقات الدفعات

### M01 — أساس Django وواجهة الخدمة

- **Goal:** أساس خادمي محلي قابل للتكرار بعد نجاح بوابة V00.
- **Scope:** تشغيل الخلفية محليًا، PostgreSQL محلي، فحص الجاهزية وعقد API أولي.
- **Out of Scope:** بيانات أعمال أو خدمة سحابية.
- **Expected files/modules:** `services/backend/config`، إعداد محلي، اختبارات التشغيل. المسارات تقديرية للمستقبل فقط.
- **DB changes:** جداول الإطار والهوية الأساسية فقط حسب العقد.
- **API changes:** health/readiness وعقد أولي.
- **Web/PWA UI changes:** لا واجهة.
- **Tests:** تشغيل نظيف، فشل DB، إعداد ناقص؛ فحص الاستجابة يدويًا.
- **Manual smoke:** تشغيل نظيف ثم تعطيل DB وفحص readiness.
- **Exit criteria:** تشغيل قابل للتكرار واختبارات ناجحة.
- **Dependencies:** M00 + اكتمال V00 وتقرير Decision Gate = GO + Mini-Contract معتمد وGO صريح لـM01.
- **Cost/account impact:** محلي؛ لا خدمة مدفوعة.

### M02 — Next.js / PWA Arabic Shell

- **Goal:** واجهة عربية متجاوبة تصلح للويب وPWA دائمين.
- **Scope:** واجهة عربية Mobile-first، فصل العام عن `/app/`، Manifest وأيقونات أولية واتصال فحص.
- **Out of Scope:** Offline كامل أو تسجيل دخول أو توصيات.
- **Expected files/modules:** `apps/web/src/app`، `components`، `lib/api`، Manifest وأيقونات. المسارات تقديرية للمستقبل فقط.
- **DB changes:** لا تغييرات.
- **API changes:** استهلاك فحص الخدمة فقط.
- **Web/PWA UI changes:** Public shell و/app وRTL وManifest وأيقونات أولية.
- **Tests:** RTL وتكبير النص والعرض الصغير؛ فتح على Chrome Android وSafari iPhone.
- **Manual smoke:** فتح shell بعرض هاتف وRTL وتكبير النص على Android وiPhone.
- **Exit criteria:** واجهة واضحة على الهاتف ورابط يعمل؛ سياسة Service Worker موثقة دون تفعيل حفظ عشوائي.
- **Dependencies:** M01.
- **Cost/account impact:** محلي؛ اختبار التثبيت الكامل على HTTPS قبل Beta.

### M03 — Web Authentication في Django

- **Goal:** هوية وجلسة ويب آمنة في الخادم.
- **Scope:** تسجيل/دخول/خروج/تحقق/استعادة بجلسات Django ومكتبات مجرّبة.
- **Out of Scope:** JWT للمتصفح، Native auth، نظام جلسات مخصص.
- **Expected files/modules:** `services/backend/modules/identity`، إعداد Cookies وCSRF. المسارات تقديرية للمستقبل فقط.
- **DB changes:** users وجلسات المكتبات وتحقق/استعادة دون ledger مخصص.
- **API changes:** csrf/register/login/logout/session/verify/reset.
- **Web/PWA UI changes:** لا UI في هذه الدفعة.
- **Tests:** CSRF على الدخول والكتابة، انتهاء جلسة، رابط منتهي، خروج؛ صندوق بريد اختبار.
- **Manual smoke:** تسجيل وخروج واستعادة في بريد اختبار وتجربة طلب بلا CSRF.
- **Exit criteria:** جلسة آمنة، وعدم اعتماد حماية الدخول على DRF الافتراضية وحدها.
- **Dependencies:** M01.
- **Cost/account impact:** لا بريد حقيقي بعد؛ صفر خدمة جديدة.

### M04 — Web Auth UI

- **Goal:** رحلة دخول عربية قابلة للاستخدام على الهاتف.
- **Scope:** شاشات التسجيل والدخول والاستعادة، ومعالجة الجلسة المنتهية.
- **Out of Scope:** حسابات اجتماعية وSMS.
- **Expected files/modules:** `apps/web/src/features/auth`، `lib/auth`، صفحات `/app/` المناسبة. المسارات تقديرية للمستقبل فقط.
- **DB changes:** لا تغييرات.
- **API changes:** ربط auth مع Cookie وCSRF.
- **Web/PWA UI changes:** نماذج دخول/تسجيل/استعادة ورسائل انتهاء الجلسة.
- **Tests:** CSRF مفقود، كلمة مرور خاطئة، رجوع بعد reset، تبويبان؛ تجربة حسابين.
- **Manual smoke:** دخول حسابين وتبويبين وreset ورابط رجوع غير مسموح.
- **Exit criteria:** لا رموز دخول في browser storage ولا تحويل إلى رابط خارجي غير معتمد.
- **Dependencies:** M02 وM03.
- **Cost/account impact:** لا خدمة إضافية.

### M05 — Household Backend

- **Goal:** إعداد عائلة واحدة ومصدر موحد لقيودها.
- **Scope:** عائلة واحدة، بلد وحصص وتفضيلات وحساسيات وممنوعات.
- **Out of Scope:** أفراد ودعوات ومزامنة متقدمة.
- **Expected files/modules:** `services/backend/modules/households` والمرجع الأساسي. المسارات تقديرية للمستقبل فقط.
- **DB changes:** household وpreferences/constraints ومالك فريد.
- **API changes:** قراءة/إنشاء/تعديل بإثبات الملكية.
- **Web/PWA UI changes:** لا UI.
- **Tests:** عزل عائلتين، حدود الحصص، فصل الذوق عن الحساسية.
- **Manual smoke:** حسابان بعائلتين وتجربة قراءة معرّف العائلة الأخرى.
- **Exit criteria:** لا تعتمد الملكية على household ID أرسله العميل وحده.
- **Dependencies:** M03.
- **Cost/account impact:** لا خدمة جديدة.

### M06 — Web Onboarding

- **Goal:** الوصول السريع لأول قرار دون إلزام Pantry.
- **Scope:** إعداد العائلة بخطوات قليلة وتعديل إعداداتها؛ Pantry خطوة اختيارية قابلة للتخطي ولا تعوق الوصول لشاشة اليوم لاحقًا.
- **Out of Scope:** أسئلة طويلة أو بيانات أفراد.
- **Expected files/modules:** `apps/web/src/features/household`، onboarding/settings. المسارات تقديرية للمستقبل فقط.
- **DB changes:** لا تغييرات.
- **API changes:** ربط M05؛ لا شرط عناصر Pantry.
- **Web/PWA UI changes:** onboarding مختصر وإعدادات؛ تخطي Pantry والوصول لليوم.
- **Tests:** رجوع بين الخطوات، فشل حفظ، Safari autofill، تكبير النص. اختبار اكتمال onboarding مع pantry=empty.
- **Manual smoke:** عائلة جديدة تتخطى Pantry وتصل لنهاية الإعداد دون طلب مكونات.
- **Exit criteria:** الحفظ المؤكد فقط يظهر ناجحًا؛ تغيير القيود يحتاج اتصالًا. لا شرط مخزون أو عناصر للانتقال.
- **Dependencies:** M04 وM05.
- **Cost/account impact:** لا خدمة إضافية.

### M07 — قاموس المكونات وإدارته

- **Goal:** مكونات خليجية مفهومة بهويات ثابتة.
- **Scope:** أسماء موحّدة ومرادفات إقليمية ووحدات وبحث بسيط.
- **Out of Scope:** AI parsing ومحرك بحث مستقل.
- **Expected files/modules:** `services/backend/modules/ingredients`، مرجع واختبارات عربية. المسارات تقديرية للمستقبل فقط.
- **DB changes:** ingredients/aliases/units/تصنيفات وحساسية مراجعة.
- **API changes:** search/resolve مع نتائج الالتباس.
- **Web/PWA UI changes:** Django Admin للقاموس؛ لا شاشة مستخدم بعد.
- **Tests:** لبن، روب، طماطم ومعجون، أخطاء كتابة.
- **Manual smoke:** البحث عن لبن وروب وطماطم ومعجون ومراجعة اختلاف المعنى.
- **Exit criteria:** المصطلح الملتبس يعيد اختيارًا لا حكمًا آليًا خطرًا.
- **Dependencies:** M05 للمرجع المشترك.
- **Cost/account impact:** وقت تحرير فقط.

### M08 — Web Ingredient Selector

- **Goal:** بحث واختيار واضحان دون تخمين معاني الكلمات.
- **Scope:** اختيار المكوّن الصحيح من الهاتف.
- **Out of Scope:** إدخال مخزون كامل أو كاميرا.
- **Expected files/modules:** `apps/web/src/features/ingredients` ومكوّن البحث. المسارات تقديرية للمستقبل فقط.
- **DB changes:** لا تغييرات.
- **API changes:** استهلاك بحث المكونات.
- **Web/PWA UI changes:** بحث عربي مع اختيار المعنى وحالات لا نتائج.
- **Tests:** لوحة مفاتيح عربية، كلمة قصيرة، no-results، خطأ شبكة.
- **Manual smoke:** بحث بلوحة مفاتيح عربية ثم قطع الشبكة واختيار مكوّن.
- **Exit criteria:** الاختيار يرسل هوية المكوّن الصحيحة.
- **Dependencies:** M06 وM07.
- **Cost/account impact:** لا خدمة جديدة.

### M09 — الوصفات ونسخها

- **Goal:** محتوى وصفات منظم يحتفظ بتاريخه.
- **Scope:** وصفة كاملة بمقادير وخطوات ووقت وحصص ومصدر.
- **Out of Scope:** توليد AI أو SEO واسع.
- **Expected files/modules:** `services/backend/modules/recipes` وAdmin. المسارات تقديرية للمستقبل فقط.
- **DB changes:** recipes/versions/ingredients/steps/source والقيود.
- **API changes:** قراءة إدارية ومسودات محددة الصلاحية.
- **Web/PWA UI changes:** Django Admin لإنشاء مسودة؛ لا نشر عام.
- **Tests:** مقادير خاطئة، خطوات ناقصة، نسخة جديدة لا تمحو القديمة.
- **Manual smoke:** إنشاء مسودة ثم نسخة جديدة والتحقق من بقاء القديمة.
- **Exit criteria:** محتوى منظم صالح للمراجعة وللاستخدام من أي Client.
- **Dependencies:** M07.
- **Cost/account impact:** إعداد محتوى منفصل.

### M10 — الاعتماد والنشر العام والسحب

- **Goal:** منع استخدام محتوى غير معتمد وفصل العام عن الخاص.
- **Scope:** مراجعة السلامة والحقوق، نشر داخل التطبيق، وخيار منفصل للنشر العام.
- **Out of Scope:** نشر آلي أو تحويل كل المكتبة لعامة.
- **Expected files/modules:** `recipes/review`، `publishing`، إجراءات Admin. المسارات تقديرية للمستقبل فقط.
- **DB changes:** حالة مراجعة واعتماد وسحب، public_slug وis_public وسجل إجراء.
- **API changes:** سياسات قراءة ونشر وسحب عامة وخاصة.
- **Web/PWA UI changes:** إجراءات مراجعة ونشر في Admin.
- **Tests:** مسودة/وصفة مسحوبة/حقوق ناقصة؛ نشر خاص ثم عام ثم سحب.
- **Manual smoke:** نشر داخلي ثم عام ثم سحب وفحص كل مسار.
- **Exit criteria:** لا وصفة عامة بلا اعتماد وحقوق؛ السحب يؤثر على مساري القراءة.
- **Dependencies:** M09.
- **Cost/account impact:** مراجعة بشرية للمحتوى؛ لا خدمة جديدة.

### M11 — تفاصيل الوصفة العامة والخاصة

- **Goal:** قراءة وصفة مناسبة في المسار العام أو الخاص.
- **Scope:** عرض وصفة داخل التطبيق، وقالب عام يستعمل Public API، مع metadata أساسية.
- **Out of Scope:** تصنيفات كثيرة أو تخصيص الصفحة العامة للعائلة.
- **Expected files/modules:** `apps/web/src/features/recipes`، `/recipes/{slug}`، `/app/recipes`، public API. المسارات تقديرية للمستقبل فقط.
- **DB changes:** نفس نماذج المحتوى.
- **API changes:** Public API منفصل وقراءة وصفة محمية.
- **Web/PWA UI changes:** صفحة عامة وداخل التطبيق وSEO metadata.
- **Tests:** صفحة عامة دون Cookie، صفحة خاصة دون جلسة، سحب وصفة، قراءة HTML العام.
- **Manual smoke:** رابط وصفة عامة في متصفح بلا جلسة وصفحة خاصة بعد logout.
- **Exit criteria:** الصفحة العامة لا تسرب بيانات خاصة؛ قالب وصفة قابل للمشاركة.
- **Dependencies:** M08 وM10.
- **Cost/account impact:** لا خدمة جديدة.

### M12 — الصور والمشاركة

- **Goal:** صور مرخصة ومشاركة لا تكشف بيانات العائلة.
- **Scope:** صور مضغوطة مرخصة، Open Graph، مشاركة عامة ونسخ رابط.
- **Out of Scope:** صور ثلاجة، رفع مستخدمين، روابط خاصة.

- **Web/PWA UI changes:** نسخة HTTPS للويب/PWA بعزل العام والخاص.
- **Tests:** Cookie/CSRF عبر التوجيه، عدم حفظ بيانات خاصة في CDN، تثبيت Home Screen ونشر تحديث.
- **Manual smoke:** زيارة HTTPS وتثبيت اختياري ونشر تحديث وتراجع مع عميل قديم.
- **Exit criteria:** نشر قابل للتكرار واسترجاع، وفاتورة مفهومة ضمن السقف.
- **Dependencies:** M23 وM25 وM26 واعتماد المزود والمنطقة.
- **Cost/account impact:** تفعيل الاستضافة؛ اختبار داخلي 30–90 دولارًا تخطيطيًا.

### M28 — نسخة احتياطية واستعادة أساسية

- **Goal:** حماية بيانات التجربة بإمكانية استعادة مجرّبة قبل دعوة العائلات.
- **Scope:** نسخة احتياطية أساسية مجدولة، تجربة restore معزولة، وتسجيل نجاحها أو فشلها. تنفذ طلبات الخصوصية الضرورية بإجراء محدود وواضح.
- **Out of Scope:** منصة مهام عامة، تنظيفات متقدمة، توافر متعدد المناطق أو أتمتة تشغيل واسعة.
- **Expected files/modules:** أوامر التشغيل وrunbooks. المسارات تقديرية للمستقبل فقط.
- **DB changes:** لا جداول جديدة افتراضيًا؛ سجل تشغيل محدود عند الحاجة، ولا queue عامة.
- **API changes:** لا API عام جديد.
- **Web/PWA UI changes:** لا UI مستخدم جديد؛ نتيجة تشغيل واضحة للمسؤول.
- **Tests:** إنشاء نسخة، فشلها، واستعادة معزولة مع احترام الحسابات المحذوفة.
- **Manual smoke:** استعادة نسخة معزولة والتأكد من إمكان استخدام البيانات وعدم إعادة حساب محذوف للخدمة.
- **Exit criteria:** نجاح restore مثبت، وزمن الاستعادة وحجم الخسارة الممكنة معروفان قبل Beta.
- **Dependencies:** M25 وM27.
- **Cost/account impact:** backup والجدولة ضمن ميزانية التجربة.

### M29 — مراجعة الويب والأمان والـPWA

- **Goal:** التحقق من رحلة المنتج والأمان على متصفحات حقيقية.
- **Scope:** اختبار رحلة القرار والطبخ عبر الإنترنت، المتصفحات، التحديث، الخصوصية، الاستعادة والفهرسة. العمل الكامل بلا إنترنت ليس شرط Beta.
- **Out of Scope:** إصلاحات واسعة بلا عقد جديد أو بناء Native.
- **Expected files/modules:** API/security tests، واختبارات Web مثل Playwright، وتقرير يدوي. المسارات تقديرية للمستقبل فقط.
- **DB changes:** لا تغيير مخطط افتراضي؛ أي إصلاح يراجع ضمن النطاق.
- **API changes:** فحص العقود والحماية؛ إصلاحات محددة فقط.
- **Web/PWA UI changes:** فحص وإصلاح رحلة RTL وCook Mode والتحديث وSEO وسهولة الاستخدام.
- **Tests:** Chrome Android، Safari iPhone، متصفح مكتبي؛ CSRF/XSS وعزل حسابات، تقدم الطبخ، update، مشاركة وnoindex.
- **Manual smoke:** رحلة كاملة على Chrome Android وSafari iPhone ومكتبي، دون Pantry ثم مع Pantry اختيارية، مع إغلاق صفحة الطبخ واستئنافها.
- **Exit criteria:** لا عيب حرج مفتوح؛ اختبار آلي لـWebKit لا يغني وحده عن iPhone فعلي.
- **Dependencies:** M24–M28 وجميع الرحلات الأساسية.
- **Cost/account impact:** أجهزة موجودة؛ خدمة اختبار مدفوعة فقط إذا احتجناها ووافقنا.

### M30 — حزم المحتوى

- **Goal:** تغطية محتوى كويتية مراجعة قابلة للاستخدام.
- **Scope:** 5–10 وصفات بالحزمة، مع مراجعة وحقوق وتغطية السيناريوهات. الأولوية لسياقات عائلات الكويت؛ دعم المصطلحات السعودية والإماراتية دون افتراض ملاءمة سعودية مثبتة.
- **Out of Scope:** نشر 150 وصفة مولّدة بلا مراجعة أو تحويلها كلها لصفحات عامة.
- **Expected files/modules:** مرجع المحتوى وسجلات الحزم. المسارات تقديرية للمستقبل فقط.
- **DB changes:** إدخال محتوى معتمد عبر Admin؛ لا schema جديد.
- **API changes:** نفس API للنشر والقراءة.
- **Web/PWA UI changes:** معاينات عامة وخاصة للوصفات؛ لا شاشة جديدة.
- **Tests:** الحصص والحساسية والخطوات والصور؛ سيناريوهات عائلات وفحص طبخ بشري حيث يلزم.
- **Manual smoke:** قراءة وطبخ بشري لعينة حسب الحاجة ومراجعة الحصص والحقوق والنسخة العامة.
- **Exit criteria:** الحزمة معتمدة؛ هدف التجربة 100–150 وصفة يُراجع بالتغطية لا بالعدد وحده.
- **Dependencies:** M10–M13، وفحص التغطية بعد M19.
- **Cost/account impact:** تحرير ومراجعة وحقوق، منفصلة عن الاستضافة؛ البطاقة تتكرر.

### M31 — Closed Beta Web/PWA

- **Goal:** تعلم من استعمال فعلي لـ20–50 عائلة في الكويت.
- **Scope:** تجربة برنامج مع 20–50 عائلة في الكويت عبر رابط مباشر، وصلاحية خادمية وقياس أربعة أسابيع أولية مقترحة بعد نضج العينة.
- **Out of Scope:** Google Play وAndroid signing وLive AI وإطلاق عام تلقائي.
- **Expected files/modules:** قائمة إطلاق التجربة وتعليماتها وخط الأساس للقياس. المسارات تقديرية للمستقبل فقط.
- **DB changes:** تفعيل أهلية Beta وإعداداتها بعد الموافقة؛ لا schema جديد افتراضيًا.
- **API changes:** نفس العقود مع صلاحيات تجربة خادمية.
- **Web/PWA UI changes:** تعريف بدء التجربة ورابط ودعم وتثبيت اختياري.
- **Tests:** رابط على Android وiPhone، تسجيل ودخول، اقتراح وطبخ، offline، تثبيت وتحديث وحذف.
- **Manual smoke:** رابط Beta على Android/iPhone: دخول، قرار بلا Pantry، طبخ، تنزيل وتحديث وحذف؛ الدعوات فقط عند اعتماد M31.
- **Exit criteria:** إطلاق تجربة بموافقة مستقلة، دعم وخصوصية وقياس يعملان، ثم تقرير استعمال/عودة وقرار Continue/Modify/Stop؛ النشر وحده ليس نجاح المنتج.
- **Dependencies:** M29 وM30 ومراجعة الخصوصية للكويت واعتماد الخدمات وموافقة توزيع التجربة؛ جميع قدرات MVP المقبولة.
- **Cost/account impact:** 40–130 دولارًا شهريًا مخصص تشغيل تخطيطي؛ سقف مقترح 150 يحتاج اعتمادًا؛ المحتوى والبحث والدعم منفصلان؛ لا حساب متجر.

## Post-MVP — V1.0 إلى V1.5

ترقيم الإصدارات هنا للمنتج ولا يغيّر Architecture Version 1.1. كل إصدار اتجاه محتمل يحتاج دليلًا وعقود دفعات جديدة؛ ليس backlog معتمدًا تلقائيًا.

| الإصدار | الهدف والنطاق المحتمل | دليل الدخول واختبار الخروج | خارج النطاق/الكلفة |
|---|---|---|---|
| V1.0 | معالجة نتائج Beta الكويتية ثم إطلاق Web/PWA محدود | عودة فعلية ورحلة مستقرة ومحتوى مناسب؛ تجربة دون دعم مكثف | لا توسع سعودي تلقائي؛ كلفة دعم ومحتوى وتشغيل |
| V1.1 | AI Chef محدود فقط إن ظهر احتياج متكرر لا تغطيه القواعد | مزود واحد ومخرجات مقيدة وسلامة وسقف إنفاق وقياس منفعة | لا توليد حر ولا تعدد مزودين؛ إن لم توجد حاجة تؤجل الفكرة |
| V1.2 | اختيار تحسين عودة واحد: تخطيط بسيط أو تذكير مناسب للويب | سبب عدم العودة مثبت وتجربة تقيس أثره لا نقراته | لا تبنّي الاثنين تلقائيًا؛ أذونات ودعم المنصة تراجع وقتها |
| V1.3 | اختبار Web Premium إذا وجدت قيمة واستعداد دفع | عرض وتجربة تسعير معتمدة وصلاحيات خادمية وفشل/استرداد مجرب | لا إعلانات أو متاجر افتراضية؛ مراجعة قانون/مزود/تكلفة |
| V1.4 | توسعة واحدة مثبتة: السعودية بعد تحقق مستقل، أو native أو نمو محتوى عام | محتوى ومقابلات/تجربة سعودية إن اختير السوق؛ وإلا بوابة المسار المختار | لا تفترض أن كل قنوات الكويت تنتقل؛ ميزانية توسع منفصلة |

الأسبوعي وAI وPremium مجرد فرضيات. Grocery/affiliate وsponsored content المعلن وads عند scale لا تنفذ دون دليل وقرار مستقل؛ لا شيء منها في MVP.

## Native Android/iOS — N01–N09، مخطط مستقبلي فقط

لا apps/mobile أو حسابات متاجر الآن. Flutter مرشح يعاد تقييمه عند قرار native؛ backend والبيانات والعقود يعاد استخدامها، واجهات React لا تنتقل تلقائيًا. لا تفتح هذه البطاقات قبل دليل الحاجة وميزانية الدعم.

### N01 — Validate native need

- **Goal:** إثبات عائق متكرر يستحق عميلًا أصليًا.
- **Scope:** مقابلات وقياس فجوة PWA وتقدير UI/دعم/متاجر ومقارنة بدائل.
- **Out of Scope:** أي بناء أو شراء حساب.
- **Expected files/modules:** تقرير قرار native ومراجعة ADR-018.
- **DB changes:** لا تغيير.
- **API changes:** لا تغيير؛ مراجعة توافق العقود.
- **Web/PWA UI changes:** لا تغيير؛ تقييم بدائل معالجة العائق بالويب.
- **Tests:** مراجعة أدلة وإسناد المشكلة.
- **Manual smoke:** إعادة إنتاج العائق على أجهزة فعلية.
- **Exit criteria:** قرار مسبب GO/MODIFY/STOP لا افتراض أن متجرًا يحل retention.
- **Dependencies:** نتائج استخدام ناضجة، قدرة مالية وتشغيلية واعتماد منفصل.
- **Cost/account impact:** وقت بحث وتقدير؛ لا حساب متجر.

### N02 — Native foundation

- **Goal:** أساس عميل Android/iOS إذا اعتمد.
- **Scope:** حسم Flutter أو البديل وRTL والتنقل واتصال بالعقود.
- **Out of Scope:** قواعد أعمال مكررة.
- **Expected files/modules:** apps/mobile مستقبلًا فقط.
- **DB changes:** لا تغيير.
- **API changes:** استهلاك readiness/config.
- **Web/PWA UI changes:** لا تغيير في الويب؛ واجهة native أولية.
- **Tests:** بناء وتشغيل واتصال وRTL.
- **Manual smoke:** شاشة على جهازين فعليين.
- **Exit criteria:** أساس قابل للتكرار دون بيانات منفصلة.
- **Dependencies:** N01=GO وعقد تقني مستقل.
- **Cost/account impact:** أجهزة وأدوات/بناء تقدّر وقتها.

### N03 — Native auth

- **Goal:** دخول إلى نفس الحساب.
- **Scope:** token flow مجرب وتخزين آمن وإلغاء واستعادة.
- **Out of Scope:** نقل Cookie تلقائي أو users جديدة.
- **Expected files/modules:** mobile/auth وbackend/identity وفق العقد.
- **DB changes:** جداول مكتبة token فقط عند الحاجة.
- **API changes:** مسارات native auth مستقلة عن جلسة الويب.
- **Web/PWA UI changes:** لا تغيير ويب مطلوب؛ نماذج native.
- **Tests:** إلغاء/تدوير/جهاز مفقود وصلاحيات.
- **Manual smoke:** نفس الحساب من PWA وnative.
- **Exit criteria:** الهوية والملكية موحدتان.
- **Dependencies:** N02 وهوية خادمية مستقرة.
- **Cost/account impact:** مراجعة أمنية؛ لا أسعار مفترضة.

### N04 — Household/Pantry

- **Goal:** نفس العائلة ومخزون اختياري.
- **Scope:** إعدادات ومخزون من API نفسه.
- **Out of Scope:** عائلة جديدة لكل جهاز وoffline writes.
- **Expected files/modules:** mobile/household وpantry.
- **DB changes:** لا تغيير افتراضي.
- **API changes:** نفس العقود القائمة.
- **Web/PWA UI changes:** لا تغيير ويب؛ شاشات native قابلة لتخطي المخزون.
- **Tests:** عزل وتعديل قديم وpantry فارغة.
- **Manual smoke:** تعديل من عميل وقراءة بالآخر.
- **Exit criteria:** بيانات متسقة ومخزون غير إلزامي.
- **Dependencies:** N03.
- **Cost/account impact:** UI واختبار فقط ضمن موازنة native.

### N05 — Recommendations

- **Goal:** نفس محرك القرار.
- **Scope:** شاشة قرار native تستهلك الخدمة القائمة دون شرط Pantry.
- **Out of Scope:** محرك موبايل أو AI محلي.
- **Expected files/modules:** mobile/recommendations.
- **DB changes:** لا تغيير.
- **API changes:** نفس generate/read/feedback.
- **Web/PWA UI changes:** لا تغيير ويب؛ بطاقات native.
- **Tests:** تطابق لنفس المدخلات والإصدارات.

- **Exit criteria:** تفسير ونتائج متسقة.

### N06 — Recipes/Cook Mode

- **Goal:** طبخ وقراءة محلية مناسبة للنظام.
- **Scope:** تنزيل نسخة وحصص وتقدم محلي ومسح حساب.
- **Out of Scope:** sync معقد وتغيير حصص offline غير محفوظة.
- **Expected files/modules:** mobile/recipes وcooking وstorage.
- **DB changes:** لا DB خادمية جديدة.
- **API changes:** عقود نسخ/سحب المحتوى الحالية.

## Critical Path والاعتماد الحقيقي

1. M00 اعتماد النطاق → V00 تحقق يدوي كويتي → بوابة GO/MODIFY/STOP.
2. عند GO فقط: M01 أساس خادم → M02 واجهة؛ M03/M04 هوية → M05/M06 عائلة وإعداد بلا Pantry.
3. M07 قاموس → M09/M10 وصفات واعتماد؛ M08 اختيار مكونات كقدرة مساعدة وM11–M13 تفاصيل وصور وحصص.
4. M17 ذاكرة طبخ → M18 قواعد → M19 عقد توصية → M20 شاشة اليوم. M16 مفضلة يغذي M21 تفضيلًا بسيطًا.
5. M14/M15 فرع Pantry اختياري يمكن تأخيره دون تعطيل M18/M19/M20. دمجه لاحقًا يختبر الرحلتين؛ عدم استخدامه من الأسرة ليس خطأ.
6. M23 طبخ أساسي وتحديث آمن → M24 قياس → M25 خصوصية أساسية؛ M26 بريد → M27 نشر → M28 نسخة واستعادة أساسية → M29 مراجعة.
7. M30 محتوى يبدأ بحزم بعد M10–M13 ويستمر خلال بقية العمل مع مراجعة تغطية بعد M19؛ لا ينتظر اكتمال كل الكود.
8. M31 Beta كويتية بعد جودة ومحتوى وخصوصية ودعم؛ ثم قرار مستقل على المنتج والتوسع. M22 تنزيل الوصفات والعمل بلا إنترنت يأتي بعد تقرير Beta فقط إذا ثبتت الحاجة.

سير العمل التشغيلي ليس ترتيبًا جامدًا لكل رقم؛ الاعتماد الفعلي في البطاقات والقرارات يحكم. M11 يستخدم selector في رحلة المحتوى حسب الخطة، لكنه لا يفرض إدخال Pantry على المستخدم. M30 حزم صغيرة متكررة بعقود واضحة، لا bulk نشر غير مراجع.

خارج المسار الحرج: Flutter وGoogle Play وApple signing وAI والدفع وإعلانات. ضمنه: HTTPS وجلسات/CSRF وفصل بيانات وPWA updates وChrome Android/Safari iPhone ونسخ واستعادة.

## Kuwait Closed Beta — 20–50 عائلة

بعد M31 المعتمد يدخل البالغ من رابط HTTPS مباشر؛ التثبيت اختياري. عينة كويتية بمالك واحد لكل عائلة، موافقة وخصوصية ودعم واضح، ولا نجمع أفرادًا متعددين كأنهم عائلات مستقلة. أربعة أسابيع متابعة أولية نطاق تخطيطي بعد تنشيط cohort، وقد تمدد إذا لم تنضج النوافذ.

معايير دخول: لا عيب أمني/سلامة حرج، محتوى يغطي الحالات الأساسية، رحلة بلا Pantry ناجحة، جلسات وتحديث وفصل حسابات واستعادة مجربة، وضع طبخ عبر الإنترنت يحفظ تقدم الخطوات، مسؤول دعم ومحتوى وحذف بيانات، موافقة الخدمات والميزانية والتوزيع. تنزيل الوصفات والعمل الكامل بلا إنترنت ليسا شرطًا لدخول Beta. لا إرسال دعوات في مهمة الوثائق.

| Acquisition | مصدر مختصر → تفعيل → عودة؛ CAC Unknown until measured بتكلفة فعلية وتعريف واضح |

نفصل web وpwa بحسب display mode الحالي، ونعد الحساب فريدًا في الإجمالي. الزيارات والتثبيت والمشاركة ليست نجاحًا بديلًا للعودة. لا ضمان retention أو نسبة نجاح من هذه الخطة. أهداف داخلية تعتمد قبل دعوة Beta، ولا تغير بعد النتائج لإظهار نجاح.

## Continue / Modify / Stop بعد Beta

- **Continue:** عائلات تعود لاتخاذ قرار عبر أسابيع دون دعم يدوي مستمر، وجودة مستقرة مع ودون Pantry، ودليل نوعي يفسر العودة وكلفة دعم قابلة للتحمل؛ يجيز مراجعة توسعة محددة فقط.
- **Modify:** اهتمام أولي مع ضعف عودة أو عبء إدخال أو نقص محتوى/متصفح؛ تحسين أكبر عائق واحد وتجربة مقارنة محددة قبل زيادة الإنفاق.
- **Stop/Pause expansion:** غياب قيمة متكررة بعد إصلاح موجّه وتجربة ناضجة، أو عائق سلامة/خصوصية/تشغيل لا يمكن تحمله. لا تعالج ذلك تلقائيًا بإضافة AI أو native أو إعلانات.
- السعودية لها بوابة تحقق مستقلة: مقابلات وسيناريوهات/محتوى ومصطلحات وقنوات وخصوصية وتجربة صغيرة مناسبة، ثم قرار scale. مؤشرات الكويت وحدها لا تكفي.

بوابة V00 لها الحدود الداخلية المسبقة في Validation Plan؛ معايير Beta العددية تضبط بعقد M31 بناءً على تعلم V00 ودون الادعاء أنها benchmarks سوقية.

## Cost assumptions والحسابات

الأرقام مخصصات تخطيطية بالدولار/شهر وليست تسعيرًا موثقًا أو موافقة شراء: محلي 0–10، اختبار داخلي 30–90، Beta 40–130، إطلاق عام صغير 75–220. سقف Beta المقترح 150 يعتمد مع عرض مزود ومنطقة وbackup قبل التزام. مثال توزيع غير ملزم: تشغيل 15–50، PostgreSQL 15–40، صور وbackup 5–20، بريد/مراقبة 0–15؛ لا يعد بند مرتين. النطاق وتجديده السنوي منفصلان.

**Software cash cost:** أدوات وتكلفة تشغيل فعلية؛ وقت المؤسس وCodex قد يقلل النقد البرمجي ولا يجعله صفر جهد. لا نفترض حاجة حتمية إلى $3,000–8,000.
**Business launch cost:** محتوى وسلامة طعام وصور/حقوق وقانون/خصوصية وتسويق وبحث ودعم وأجهزة ووقت مؤسس؛ تضاف إلى التشغيل الفعلي دون عد مزدوج للاستضافة. لا CAC محدد أو break-even ثابت أو valuation/equity. CAC = Unknown until measured.

M00 وإعداد الوثائق لا يحتاجان حسابات. V00 خطة فقط الآن؛ أي قناة وحافز لهما اعتماد قبل التجربة. البريد/النطاق في M26 والاستضافة في M27 لهما موافقات فعلية لاحقة. لا AI API أو Play/Apple account في MVP.
